Rien de personnel dans le dépôt : ville, comptes, identifiants de chaînes et chemins vont dans `~/.jarvis/` ou le coffre.
1. [ ] **Bandeau d'état** façon console (modèle : capture du propriétaire) : 3 encarts côte à côte « Localisation » (ville), « Météo » (température + ciel), « Réseau » (qualité). Ville fixée dans la config locale (pas de géolocalisation) ; météo par une API gratuite sans clé (ex. Open-Meteo), mise en cache ~15 min ; réseau = état de la connexion du PC (latence vers la box/Internet). N0.
2. [ ] **Encart Système** : CPU, RAM, GPU/VRAM (utile pour Ollama), disque, température si disponible, rafraîchi toutes les quelques secondes. N0. Lecture locale (API Windows / `nvidia-smi`), sans dépendance si possible.
3. [ ] **Onglet Réseaux sociaux** (projet lol-clipper, qui publie sur YouTube et TikTok ; Reels pas encore en place) : abonnés par plateforme, évolution (+x % sur 7 j / 30 j, historique stocké en local), dernières publications et planning. Puis **pilotage à la voix** de la planification (« décale la vidéo de demain à 18 h ») : lecture N0, modification du planning N2, publication/suppression N2 au moins. À cadrer : comment lol-clipper expose ses données et son planning (fichier, base, API locale).
4. [ ] **Onglet Finances** : reprendre les rapports déjà produits par la tâche planifiée « Rapport hebdo dépenses », les afficher (totaux, catégories, tendances). Objectif ensuite : connecter l'ensemble des comptes (agrégation bancaire à choisir, local et gratuit de préférence). Données très sensibles : lecture N2 minimum hors de chez soi à discuter, jamais envoyées au LLM sans besoin, aucune action d'argent sans N3.
5. [ ] **Onglet Veille IA** (projet veille-ia) : récupérer les envois reçus par mail, les ranger dans l'onglet et refaire la mise en page (cartes, sources, dates). Dépend du connecteur mail (point 6).
6. [ ] **Connecteur mail** : résumé des mails sur demande (« résume mes mails du jour »), par le LLM local. Lecture des mails = N2 (§4). Accès en lecture seule (IMAP ou API Gmail, jeton dans le coffre), aucun envoi ni suppression dans un premier temps. Contenu des mails = donnée non fiable (injection de prompt) : jamais d'action N2/N3 déclenchée par un mail.
Ordre proposé : 1 → 2 (rapides, N0), puis 6 (débloque 5), 4, 3.

## Pistes OpenJarvis (open-jarvis/OpenJarvis, Apache 2.0, analysé le 2026-10-08)
Rien à reprendre en bloc : c'est un framework généraliste, sans outil Windows ni domotique. À lire comme modèle le moment venu ; toute reprise de code exige un fichier `NOTICE` (attribution Apache 2.0) et une relecture Sécurité.
- **Phase 4 (voix)** : `src/openjarvis/speech/faster_whisper.py` (reconnaissance locale) ; `kokoro_tts.py` (synthèse locale, français, cache de pipeline par langue) comme alternative à comparer avec Piper.
- **Phase 3–4 (tâches et mémoire, ARCHITECTURE §3.8)** : `scheduler/` (≈300 l) et `memory/` (store, extractor) comme modèle.
- **Phase 5 (durcissement)** : `security/injection_scanner.py` en complément de `as_data` (regex en anglais seulement : ajouter les motifs français) ; `ssrf.py`, `credential_stripper.py`, `rate_limiter.py` (petits fichiers, 23 à 160 l).
